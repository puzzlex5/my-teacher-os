# 01. Product Principles

## 1. Accuracy first

Teacher OS의 모든 자동화는 정확도를 최우선으로 한다.

- 고신뢰 정보만 자동 반영
- 애매하거나 충돌하는 정보는 검토 상태
- 검증되지 않은 추론을 confirmed 데이터로 저장하지 않음
- 데이터가 없다는 사실과 데이터를 불러오지 못했다는 상태를 구분
- 실제 공식 자료와 사용자 학교 자료가 우선

예:

- 잘못: `오늘 수업 0건`
- 올바름: `오늘 수업 여부를 확정할 수 없습니다.`

## 2. Re-entry Zero

이미 존재하는 학교 자료를 다시 입력시키지 않는다.

가능한 입력원:

- 학사일정
- 교사 시간표
- 컴시간
- 평가계획서
- 업무분장표
- 학교교육계획
- 공문
- Excel/CSV
- HWP/HWPX
- PDF
- DOCX/PPTX
- 이미지/OCR

기본 흐름:

`자료 제공 → 문서 종류 판별 → 정보 추출 → 신뢰도 판단 → 연결 → 필요 시 최소 검토`

## 3. Context before feature

새 기능은 독립적인 메뉴가 아니라 기존 Teacher OS 데이터와 연결될 때 가치가 있다.

좋은 예:

`평가계획 → 평가일 → 시간표 → 남은 수업 횟수 → 반별 진도`

나쁜 예:

기존 데이터와 연결되지 않는 별도 체크리스트 앱을 하나 더 만드는 것.

## 4. Teacher Desk first

사용자가 가장 자주 보는 곳은 `오늘`이다. 전체 기능은 결국 오늘의 다음 행동을 더 정확하게 만들기 위해 존재한다.

오늘 화면의 이상적인 우선순위:

1. 다음 교시/수업
2. 직전 진도와 오늘 시작점
3. 오늘 일정과 마감
4. 필요한 자료
5. 빠른 연락처/검색
6. 긴 메시지·공문 정리

출석처럼 공식 시스템과 중복되고 수동 입력 부담이 큰 기능은 기본 핵심으로 넣지 않는다.

## 5. Confidence-aware automation

모든 자동화는 가능하면 다음 상태를 가진다.

- confirmed / known
- suggested / review
- unknown / unavailable
- failed / mismatch

`unknown`을 `none`으로 바꾸지 않는다.

## 6. Local-first sensitive data

민감문서 사용을 금지하는 것이 아니다.

원칙은:

> 민감문서는 로컬 우선 처리, 외부 유출 금지.

브라우저/기기 안에서 읽기·분류·검색·요약·연결할 수 있다. 외부 전송은 명시적 승인과 안전한 비공개 구조가 생기기 전에는 자동화하지 않는다.

## 7. Web-first architecture

Teacher OS의 본체는 웹이다.

이유:

- 설치 없이 학교 PC에서 사용
- 휴대폰/태블릿 접근
- 즉시 업데이트
- 향후 기기간 동기화 확장성

Windows Companion은 폴더 감시, 파일 시스템 자동화, OS 알림처럼 웹이 구조적으로 해결하기 어려운 반복업무가 실사용에서 충분히 확인될 때만 추가한다.

## 8. External products are references

TeacherDesk, Google Workspace, Microsoft 365, Notion, Obsidian, Todoist, LMS, AI 문서도구 등은 참고한다.

채택 기준:

- 정확도가 올라가는가
- 반복업무가 줄어드는가
- 수동 입력이 줄어드는가
- 기존 Teacher OS 데이터와 연결되는가
- 반복 사용 가치가 있는가
- 개인정보/보안 원칙을 지키는가
- 이미 있는 기능과 중복되지 않는가

## 9. Build for school changes

특정 학교·특정 학년·특정 업무에 고정하지 않는다. 교사가 중학교에서 고등학교로 이동하거나 학년도가 바뀌어도 데이터와 워크플로가 이어지는 구조를 지향한다.

정책 데이터는 연도와 학교급에 따라 달라질 수 있으므로 코드에 영구 고정하지 않고 공식 최신 지침을 우선한다.
