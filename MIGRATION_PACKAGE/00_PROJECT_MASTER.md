# 00. Project Master

## 한 문장 정의

**교사가 학교에 출근해서 퇴근할 때까지 필요한 정보를 Teacher OS가 먼저 알고, 정확하게 준비해서, 가장 적은 조작으로 일을 끝내게 하는 시스템.**

## 핵심 문제

교사는 이미 학교에서 학사일정, 시간표, 평가계획, 업무분장, 학교교육계획, 공문, 학생 관련 자료를 받는다. Teacher OS는 이 정보를 다시 입력시키는 프로그램이 아니라 **기존 자료를 읽어 구조화하고 서로 연결하는 운영체제**를 지향한다.

## 최상위 우선순위

1. 정확도
2. 속도
3. 자동화 범위와 기능 수

정확도를 낮춰 속도를 얻지 않는다. 동일 정확도라면 더 빠르고 단순한 구현을 선택한다.

## North Star Workflow

`다음 수업 → 컴시간 실제표 확인 → 반 확인 → 직전 수업 내용 → 현재 진도 → 오늘 시작점 → 필요한 자료`

수업 이후에도 교사가 별도 기록을 반복하지 않도록 실제 수업 흐름에서 반별 진도와 다음 시작점을 자동 갱신하는 방향을 추구한다.

## 제품 철학

- TeacherDesk 등 외부 제품은 참고자료일 뿐 blueprint가 아니다.
- 좋은 원리만 흡수하고 Teacher OS 고유 워크플로를 설계한다.
- 기능 수보다 교사의 반복업무 감소를 우선한다.
- '없음'과 '불러오기 실패/미확인'을 절대 같은 상태로 취급하지 않는다.
- 확실하지 않은 정보는 자동확정하지 않는다.
- 고신뢰 자동화, 저신뢰 검토의 원칙을 전체 시스템에 적용한다.
- 민감한 학교 자료는 사용할 수 있어야 하지만 외부로 유출되면 안 된다.
- 웹앱이 본체다. Windows Companion은 실사용에서 웹 한계가 반복적으로 확인될 때만 추가한다.

## 제품 범위

Teacher OS는 다음 영역을 하나의 데이터 흐름으로 연결한다.

- 오늘 업무판
- 학사일정
- 시간표 및 컴시간
- 반별 수업 진도
- 수업·평가
- 학생 관찰 및 학생부 작성 보조
- 행정업무
- 동아리
- 학교 문서 자동분류·추출
- 문서 버전관리
- 검색
- 자료함
- 로컬 백업·복구
- 모바일 사용

## 현재 개발 전략

공개 `main`은 안정판을 유지한다. 대규모 구조 통합은 `v1-consolidation`에서 진행하고, 기존 기능·데이터 호환·개인정보·모바일·복구 검증을 모두 통과했을 때만 공개 1.0으로 전환한다.

## 절대 하지 말 것

- 단순히 새 기능을 위해 v33, v34 식 레이어를 계속 쌓는 것
- 확인되지 않은 데이터를 확정값으로 저장하는 것
- 학생 민감정보를 테스트 fixture나 공개 저장소에 넣는 것
- 실사용 데이터 손실 가능성이 있는 마이그레이션을 자동 강행하는 것
- TeacherDesk UI/코드/저작물을 복사하는 것
- 모델의 추측을 공식 지침처럼 저장하는 것
